# Несправності та їх усунення

[← до головної](../../README.uk.md) · [English](../en/troubleshooting.md)

## Прошивання

| Що бачите | Причина | Що робити |
|---|---|---|
| порту немає | кабель без даних; немає драйвера CH34x | інший кабель; драйвер із сайту WCH |
| «Failed to connect», «No serial data received» | плата не увійшла в режим прошивання | затиснути BOOT, коротко RESET, відпустити BOOT, повторити |
| помилки посеред запису на модулі передавача | міст CH340 не тягне швидкість; мало струму | `--baud 230400` або `115200`; живлення 5 В ≥ 1 А |
| після прошивання екран передавача темний | плата ще «приймач без екрана» | у порт: `t`, потім `b1` |
| порт «зникає» під час роботи модуля | живлення від порту ноутбука | окремий блок 5 В |

## Передавач

| Що бачите | Причина | Що робити |
|---|---|---|
| порт передавача мовчить або сипле «сміттям», відповідей на команди немає | в ефір іде звук із входу PCM1808: його головний такт займає вивід TXD, яким передавач друкує в порт | увімкнути перевірочний звук («Перевірка» або `g5` наосліп) — порт заговорить (з 2.56); або перемкнути вхід на вбудований АЦП (`a0`) — лише для налагодження |
| звук у приймачах пропадає на частки секунди, мигає «немає сигналу» | вхід передавача — вбудований АЦП: з ним радіо передавача часом «стає» і оживляється за 0,2 с (у порту рядок «# РАДІО СТАЛО…») | вхід PCM1808 («Звук» → «Вхід»); на вбудованому АЦП це неминуче |
| «ТИХО НА ВХОДІ», рівень на нулі | немає сигналу з пульта; не той вихід | перевірити кабель і рівень; «Перевірка» → якщо приймачі чують перевірочний звук, справа у вході |
| «ПЕРЕВАНТАЖЕННЯ», на приймачах «Гучно на вході!» | рівень із пульта завеликий | зменшити на пульті або «Підсилення входу» в мінус |
| гул 50 Гц | «земляна петля» між пультом і блоком живлення | ізолятор 3,5 мм; живити від того ж подовжувача, що й пульт |
| приймачі чують уривками, «до ефіру» велике | зайнятий канал | «Знайти вільний канал»; «Канал при заторі: сам»; нижча якість («мова») |
| слабкий сигнал на всіх приймачах | немає зовнішньої антени на модулі «1U» | під'єднати антену 2,4 ГГц; потужність 20 дБм |
| якість «мова — за швидкістю» | вибрана якість не вміщується у швидкість | підняти швидкість радіо або лишити як є |
| картка «не відповідає» | не FAT32; поганий контакт | відформатувати (Файли → Інше → Форматувати) — **зітре все**; команда `D` покаже причину |
| картинка блимає під час оновлення | так задумано: запис у флеш зупиняє виведення кадру | чекати, живлення не вимикати |
| `?` каже «два кадри в пакеті поки не можна: приймач … зі списку не повідомляв версію 2.60 або новішу» | у списку приймачів є приймач зі старою прошивкою або такий, якого передавач після оновлення ще не чув | увімкнути цей приймач поруч — оновиться сам; якщо його вже немає — видалити зі списку («Приймачі» → приймач → «Видалити з набору»). Доти передавач працює одиночними пакетами, як раніше |
| у порту «# РАДІО СТАЛО…» | драйвер Wi-Fi перестав відповідати | нічого: передавач оживляється сам за секунди; рядок і файл у `/LOG/` надішліть розробнику |
| передавач перезапустився сам | дивитися `?` → «запуск через…» | «ПРОСІДАННЯ ЖИВЛЕННЯ» — блок живлення; «ЗАВИСАННЯ», «ЗБІЙ» — зняти знімок збою (див. [Розробка](development.md#знімок-збою)) |
| вікно «Оновлення» каже «файл не годиться» | файл пошкоджено при копіюванні або це не прошивка набору | скопіювати заново; звірити SHA-256 із `ВЕРСИЯ.txt` |
| пропонує «старішу» прошивку | на картці лишився старий файл | видалити його з `UPDATE` |

## Приймач

| Що бачите | Причина | Що робити |
|---|---|---|
| екран темний, звук є | екран не знайдено (живлення, SDA/SCL); екран погашено з меню | VCC на 3V3, SDA=8, SCL=9; поворухнути ручку |
| приймач грає, а в списку передавача він «не на зв'язку» | передавальна частина радіо приймача стала (приймання при цьому працює); до 2.63 лікувалося лише перезапуском приймача | з 2.63 нічого: приймач помічає це сам за 0,5–25 с і перезавантажує радіо (звук уривається на 20 мс), у крайньому разі раз перезапускається (секунда тиші). Запис про випадок — у журналі на картці передавача (`# [номер] приймач: …`); лічильники — у звіті `?` приймача |
| хлопок у навушниках при вмиканні чи перезапуску приймача | ЦАП відкривався раніше, ніж приймач завантажився | прошивка 2.63 (XSMT — на вивід 14); якщо хлопок при вмиканні живлення лишився — резистор 10–47 кОм між XSMT і «землею» ([обладнання](hardware.md)) |
| «НЕ ПІДКЛЮЧЕНО», коду немає, «увімкніть передавач» | передавача не чути | увімкнути передавач, піднести ближче |
| є код, але на передавачі запиту немає | вікно додавання закрите | «Приймачі» → «+ Додати» |
| «ПОШУК ПЕРЕДАВАЧА», потім сон | передавач вимкнений або на іншому каналі («Тиша» на передавачі тут ні до чого: при тиші пакети йдуть) | увімкнути передавач; у меню приймача «Канал» поставити «авто» |
| «НЕМАЄ СИГНАЛУ» час від часу | далеко; тіло людини затуляє; зайнятий ефір | ближче до передавача; антену передавача вище голів; якість «мова» чи «дальня»; швидкість «сама» |
| звук є, але з короткими провалами | втрати пакетів більші, ніж перекривають копії; замалий запас | «Запас» лишити «сам»; нижча якість; інший канал |
| звук «пливе» за висотою | дуже нерівний ефір | збільшити «Запас» вручну (15–25 мс) |
| тихо навіть на 100 % | навушники напряму мають малу віддачу; ввімкнена «Межа гучн.» | перевірити «Межа гучн.»; підсилювач навушників; навушники з більшою чутливістю |
| звук лише в одному вусі / «навиворіт» | «Виводи» не відповідають під'єднанню; баланс | навушники напряму — «2 канали»; «Баланс» — «рівно»; «Навушники → тест» покаже, де ліве й праве |
| звук пропав, а приймач на зв'язку й у ефірі звук | застрягла обробка звуку (до 2.84 — «не число» у фільтрах, лікувалось лише перезапуском) | з 2.84 приймач відновлюється сам за 1,5–6 с; вручну — меню «Перезапуск» або «Перезапустити» у вікні приймача на передавачі (`E2 <номер>` з порту) |
| вибір швидкості чи якості на передавачі нічого не змінює | далекий приймач чує слабо, і передавач тримає 1 Мбіт/с для всіх (рядок «5.5 (зараз 1)») | так задумано; на екрані сказано, хто чує слабо. Тримати обране завжди — «Ефір» → «Слабкий сигнал» → «не знижую» (далекий приймач тоді може втрачати звук) |
| звук запізнюється, «луна» з живим голосом у залі | пакети чекають ефіру (поруч сильна мережа Wi-Fi) — приймачі тримають більший запас | рядок на «Ефірі» «пакети чекають ефіру до X мс»; інший канал — далі від сильних мереж («Знайти вільний канал» з 2.82 це враховує) або «Канал при заторі: сам» (м'який перехід з 2.83) |
| PCM5102 мовчить | **XSMT модуля «в повітрі»** (перемичка H3L не запаяна): дріт від XSMT до виводу 14 приймача або до 3V3; не вибрано вихід PCM5102; SCK «у повітрі»; переплутані BCK/LCK/DIN | меню «Вихід звуку: PCM5102»; SCK на вивід 10 або на «землю»; перемичка 3 на «H»; `n8=7` покаже, чи йдуть такти — див. [Обладнання](hardware.md#зовнішній-цап-pcm5102-на-приймачі) |
| PCM5102 хрипить, тріщить, «перевантажує» на гучному; у звуку цифровий «бруд», фонове дзижчання | керівні виводи модуля FLT, DEMP, FMT «у повітрі» (перемички на звороті не запаяні) | запаяти H1L, H2L, H4L (перевірено на приладі: H1L → H, H2L → H, H4L → L — бруд зник; за документацією на мікросхему годяться й усі три на «L») або з'єднати FLT, DEMP, FMT із GND (вивід G на гребінці модуля); `n8=9` покаже, що сам сигнал до ЦАП правильний |
| Звук «зернистий», «піщаний» на верхах — навіть при ідеальному сигналі й без шумозаглушення; помітніше в стерео й з еквалайзером, що піднімає верх | до 2.86: різниця каналів у стерео йшла 4-бітною (її шум на верхах майже дорівнював музиці); на ЦАП ішло 16 біт із відкиданням дробу (на малій гучності приймача — 5–10 розрядів); обмежувач при великому «Підсиленні» без «Стискання» зрізав піки | оновити передавач і приймачі до 2.87+; `?` передавача має писати «різниця каналів БЕЗ стиснення»; при «Підсиленні» понад +6 дБ на повній гучності ввімкнути «Стискання» 1–3; порівняти на слух — `Qr0` (як до 2.86) / `Qr1` |
| Звук чистий, але періодично чути короткий шелест, ніби втрачаються пакети | 2.86: запасні копії різниці каналів були 4-бітними — кожен загублений пакет на 4 мс повертав «зерно» | оновити до 2.87+ (одиночна втрата відновлюється біт у біт); `n8=8` приймача: «кадрів із запасних копій … із них точних» — неточні лише при двох втратах поспіль. Якщо втрат багато і при сильному сигналі (−40…−55 дБм) — завади на каналі: інший канал |
| Меню й аналізатор спектра на головній приймача «гальмують», особливо з шумозаглушенням | до 3.02 екран і звук були на одному ядрі, і тракт звуку (з 2.86 — важчий, із шумозаглушенням у стерео — 83–93 % ядра) не лишав екрану часу: 17–30 кадрів/с замість 60 | оновити до 3.02+; `G1` → «екран: 62–63 кадрів за секунду»; приймача `Y15` — тракт у середньому 480–630 мкс на 1 мс |
| Із шумозаглушенням чути клацання, «пропадає один канал» | до 2.89 різниця каналів оброблялася не так, як середина (одним загальним числом), — стерео розвалювалося; до 2.92 черга виходу на ЦАП 2 мс не вміщала найважчий блок | оновити до 2.92+; `n8=8` приймача: «вихід лишався без даних 0 раз» |
| Оновлення приймачів по радіо триває хвилини, «прийом» і «запис» ледь повзуть | до 2.90 звуковий тракт (особливо з шумозаглушенням) рахував тишу під час оновлення | після оновлення до 2.90+ наступні — близько хвилини; поки на приймачах старіша версія — на час оновлення вимкнути шумозаглушення (`i16=0@номер`) |
| CS4344 мовчить | не вибрано вихід CS4344 («Вихід звуку» → CS4344 або `o2`); немає головного такту: MCLK не на виводі 10 або вивід 10 на «землі» (тоді `n8=7` пише «ВИВІД 10 НА «ЗЕМЛІ»» — прибрати замикання, напр. старий дріт SCK від PCM5102); переплутані SCLK/LRCK/SDIN (11/12/13); модуль живиться від 5 В без свого стабілізатора — «одиниця» для нього від 3 В | `n8=7`: виводи 10–13 мають «тремтіти», рядок «головний такт … ділення 20 ціле → 8.000 МГц»; живлення VCC — від 3V3 |
| CS4344 тихий, на гучному спотворює | навушники прямо в гніздо модуля: вихід лінійний, навантаження — від 3 кОм | підсилювач навушників MAX97220 (hardware.md, розділ CS4344); йому можна дати підсилення 2 |
| з CS4344 звук з'являється на пів секунди пізніше після вмикання чи пробудження | так працює захист від клацань у самій мікросхемі (Popguard: вихід плавно встає 0,25–0,42 с) | нічого робити не треба |
| шум у тиші | однобітний вихід без фільтра; живлення | RC-фільтр за схемою; інший блок/повербанк; `X` з передавача — перевірка, звідки шум |
| клацання при ввімкненні/засинанні | немає розділових конденсаторів | зібрати вихід за схемою |
| ручка крутить «не туди» | переплутані виводи A і B | поміняти місцями 5 і 6 |
| приймач не прокидається від передавача | вимкнений з передавача | на передавачі ввімкнути перемикач у рядку приймача (своєю ручкою приймач не вмикається; якщо передавача більше немає — кабель і команда `K0`, приймач попросить доступ заново) |
| повербанк вимикається, коли приймач спить | повербанк вимикає малий струм | повербанк із режимом малого навантаження або акумулятор із платою живлення |
| «потрібен USB (раз)» при оновленні | стара розмітка пам'яті без другого розділу прошивки | один раз прошити кабелем |
| «забракло пам'яті» при оновленні | плата без PSRAM | потрібна плата N16R8 |
| зависання й перезапуск від натискання ручки | версії до 2.33: переривання кнопки, що лишалося після сну | оновити до 2.34 |

### Кольоровий екран (з 3.03)

| Що бачите | Причина | Що робити |
|---|---|---|
| кольоровий екран темний, приймач працює з OLED | з 3.13 екран вибирає перемичка: вивід 21 не з'єднано з GND | поставити перемичку 21–GND і перезапустити приймач; `n14` скаже, який екран зараз |
| на OLED напис «Кольоровий екран — OLED: зніміть перемичку 21-GND» | перемичку поставлено, працює кольоровий; OLED лише підказує, як повернути себе | нічого: за 10 с OLED згасне. Повернути OLED — зняти перемичку й перезапустити |
| перемичка стоїть, а екран темний | немає живлення 3V3, не під'єднано BLK або CS | перевірити дроти за схемою; `n14` — «перемичку поставлено, але кольоровий не запустився» означає, що не вистачило пам'яті або не запустилась шина |
| червоне й синє переплутані | інший порядок кольорів у модулі | `n27=2` (BGR), перезапуск |
| картинка догори дриґом | модуль повернутий | `n27=1` (до наявних бітів додати 1) |
| на екрані «сміття», смуги | довгі дроти й слабкі виходи шини | вкоротити дроти; спробувати сильні виходи `n27=16` |
| легкі клацання в навушниках, коли змінюється картинка | наведення від шини екрана (не радіо: звук і пакети не страждають) | з 3.11 шина 20 МГц зі слабкими виходами — клацання ледь чутні. Ще тихіше — резистори 33–68 Ом у SCL і SDA, дроти подалі від дротів ЦАП, окрема «земля» модуля. Послухати: `Y23` (8 с без упину) |
| перезапуск посеред оновлення по радіо (до 3.06) | сторож задач: екран не віддавав ядро | оновити до 3.06 і новіше (одноразово — переключивши приймач на OLED) |

## Набір 4.x: міст

| Що бачите | Що зробити |
|---|---|
| «Цифровий вхід»: немає сигналу | кабель і варіант вхідної схеми ([Набір 4.x](next-edition.md#цифровий-вхід--варіанти)); на пульті цифровий вихід увімкнено й призначено джерело; частота — 48 кГц (міст бере 44,1 і 48). Звуковий трансформатор розв'язки (XH-M372 тощо) сигнал AES **не пропускає**. Порт передавача `C`: рядок AES — «є 48000 Гц / ловлю / немає» |
| AES «ловлю», «частота, якої міст не бере» | на пульті 96 кГц чи інша — поставити 48 кГц |
| Аналог глухий, «самі низи» | не зняті два вхідні конденсатори модуля PCM1808 (фото в [Набір 4.x](next-edition.md#що-докупити-й-переробити)) |
| Аналог: гул 250 Гц і гармоніки | «Аналоговий вхід» → варіант «… гул радіо прибирати» (з коробки). Він вчиться в паузах: після першого ввімкнення дайте кілька секунд тиші на вході. Гул «землі» 50 Гц — розв'язка землі на аналоговому вході або симетричний режим |
| Аналог: лівий і правий переставлені | FMY (FMT) модуля не на GND: міст розраховує на I2S (FMT, MD0, MD1 — на GND) |
| На головній «міст мовчить» | проводи H1 ↔ міст ([таблиця](next-edition.md#підключення-моста)): TXD → GP5, IO40 ← GP4, IO1 → GP6, IO2 → GP7, GND; живлення моста (5V через діод на VSYS або USB). Синій світлодіод моста: раз на секунду — працює, часто — немає тактів передавача |
| Міст не оновився / «оновлення: НЕ ВДАЛОСЯ» | порт передавача `C9` — спробувати ще; не вийшло — записати `bridge-full.uf2` наново ([Встановлення](install.md#міст-raspberry-pi-pico)) |
| macOS «завис» після під'єднання Pico | диск RPI-RP2 на macOS 15 вішає систему — не відкривати його, писати picotool (`4 Прошить мост.command`) |
| Після переходу з 3.x приймачі на старій версії | вони мають бути ввімкнені й на зв'язку; «Приймачі» → «Оновлення» → «Оновити» або дочекатися автооновлення |
| Передавач 3.x «не бачить» файл 4.x на картці | так і має бути: 4.x на передавач 3.x ставиться кабелем один раз ([Перехід](next-edition.md#перехід-із-3x-на-400)) |

## Як зібрати відомості для розробника

1. `?` у порт передавача й приймача — версія, налаштування, причина запуску.
2. `P` на передавачі — список приймачів.
3. `python3 tools/txlog.py ПОРТ 120 > log.txt` — дві хвилини друку.
4. Якщо був збій — знімок збою ([Розробка](development.md#знімок-збою)) і файли з `/LOG/` на картці.

## Повернення до заводського стану
- Передавач: «Налашт.» → «Скинути все» (роль і вид плати зберігаються). Приймачі доведеться додати знову, якщо
  стерти й ключ: `K0`.
- Приймач: меню → «Забути набір».
- Повністю: `esptool --chip esp32s3 --port ПОРТ erase-flash` і прошити заново.
