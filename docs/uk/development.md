# Розробка та налагодження

[← до головної](../../README.uk.md) · [English](../en/development.md)

## Середовище
- Arduino IDE 2.x або `arduino-cli`; ядро **esp32 3.3.3** (ESP-IDF 5.5); бібліотека **U8g2**.
- Python 3 з Pillow (картинки імітаторів), компілятор C++ (імітатори на комп'ютері).
- Збирання: `./build.sh hearlink s3 [порт]`; результат — `build/hearlink-s3/hearlink.ino.bin` (файл оновлення) і
  `hearlink.ino.elf` (**зберігайте поруч із .bin** — без нього знімок збою не розібрати).

## Порядок роботи з версією
1. Змінити `FW_VERSION` у `hearlink/config.h`.
2. `python3 tools/make_lang.py` — має бути «без перекладу: 0».
3. `tools/simrx/run.sh` і/або `tools/sim/run.sh` — подивитися картинки екранів, які змінювалися.
4. Зібрати, залити **в передавач** кабелем; приймачам — по радіо: команда `M1` або вікно «Оновлення».
5. Перевірка на залізі (нижче). Тільки потім — «готово».
6. `tools/make_kit.sh` — набір для прошивання; зберегти копію вихідних текстів і `.elf`.

Правила, яких тримається код:
- нові поля налаштувань — **тільки в кінець** `Settings`;
- формат оновлення по радіо не змінюється; нові можливості — новими видами пакетів або новою довжиною;
- у кожного виду шифрованого повідомлення свій номер виду (`SEC_…`);
- нові великі буфери — у PSRAM; у передавача має лишатися не менше 40 КБ вільної внутрішньої пам'яті;
- усе, що показує «працюю», мусить рухатися; новий напис — українською в коді й переклад у `tools/lang_en.py`.

## Обов'язкова перевірка після кожної зміни

```
# ефір: 60 с, передавач і приймач на кабелях
QUIET=1 python3 tools/watch2.py ПОРТ_ПЕРЕДАВАЧА ПОРТ_ПРИЙМАЧА 60
#   очікування: відмов 0, пропущено 0, провалів у приймача 0 мс

# сон і пробудження
python3 tools/sleeptest.py ПОРТ_ПЕРЕДАВАЧА 4:z1 26:z0 конец:42
#   очікування: «не на зв'язку» → після z0 «СПИТЬ, вихід СТОЇТЬ» → за 2–5 с «вихід живий»

# ручка після сну й після оновлення по радіо (по радіо, з порту передавача)
python3 tools/txlog.py ПОРТ_ПЕРЕДАВАЧА 30 '1:G1' '3:@* n8=1' '6:@* n8=1000' '10:@* n7=3' '13:@* n8=3' '15:@* n8=4' '18:@* ?' '25:G0'
#   очікування: вид переривання 0, дозволено 0; після натискань «працює N с» не скинулося
```

Частота кадрів екрана приймача — у його звіті («екран: 62 кадрів за секунду»). Плавність екрана передавача —
`tools/fliptest.py`, `tools/idletest.py`.

## Імітатори екранів
- **Передавач**: `tools/sim/run.sh` збирає справжній `txui.h` із заглушками й кладе знімки сторінок у
  `tools/sim/out/`. Сцени — у `tools/sim/sim.cpp` (дотики `tap(x, y)`, збереження `save("назва")`).
- **Приймач**: `tools/simrx/run.sh` збирає справжній `rxscreens.h` з бібліотекою U8g2, робить кадри кожні 40 мс,
  аркуш ключових кадрів `out/kadry.png` і анімацію `out/pryimach.gif`.
- Зміну малювання перевіряти **картинкою**, а не лише станом програми.

## Перевірка звуку й шифру на комп'ютері
`tools/host/run.sh`: бере справжній `proto.h` і проганяє звук через усі чотири якості з втратами 0, 5 і 20 %;
стерео — сигнал/шум по каналах і просочування; `sec_test.cpp`, `sec_kat.py` — перевірка шифру за еталонами.

## Знімок збою
При збої плата друкує в порт «Guru Meditation Error…» із причиною та адресами й зберігає знімок у розділ
`coredump`. Розбір без сторонніх програм (усе є в пакунках Arduino):

```
E=~/Library/Arduino15/packages/esp32/tools
# 1. зчитати розділ
$E/esptool_py/*/esptool --chip esp32s3 -p ПОРТ -b 460800 read_flash 0xFF0000 0x10000 core.bin
# 2. відрізати 24 байти заголовка (перші 4 байти — довжина)
python3 -c "import struct;d=open('core.bin','rb').read();n=struct.unpack('<I',d[:4])[0];open('core.elf','wb').write(d[24:n])"
# 3. що робили всі задачі
$E/xtensa-esp-elf-gdb/*/bin/xtensa-esp32s3-elf-gdb -batch -ex "info threads" -ex "thread apply all bt" hearlink.ino.elf core.elf
# окрема адреса зі звіту
$E/esp-x32/*/bin/xtensa-esp32s3-elf-addr2line -pfiaC -e hearlink.ino.elf 0x4038175f
```

Причина запуску — в `?`:

| Напис | Що означає |
|---|---|
| увімкнення живлення | звичайний запуск, скидання кнопкою чи кабелем |
| перезапуск програмою | оновлення, команда, меню |
| ПРОСІДАННЯ ЖИВЛЕННЯ | блок живлення не тягне |
| ЗБІЙ ПРОГРАМИ | виняток — знімати знімок |
| ЗАВИСАННЯ (сторож переривань) | переривання без кінця або надто довга критична ділянка |
| ЗАВИСАННЯ (сторож) | задача на ядрі 0 не віддає процесор |

## «Чорна скринька» радіо
`Q` — лічильники, останній зліпок і події цієї хвилини. Зліпок: секунда, канал, скільки пакетів у драйвера, скільки
він мовчав, код помилки, пам'ять, і 40 подій перед відмовою з часом відносно неї (зміна каналу, перехід, вимір
каналів, запис налаштувань, картка, повідомлення, команда порту, сторінка екрана, спроби оживлення).

## Як додати…

**…налаштування приймача, кероване з обох боків:**
1. поле в кінець `Settings` (`config.h`) + перевірка меж у `settingsLoad`;
2. номер `RXP_…` у `proto.h`, гілки в `rxParamGet` / `rxParamSet` (`rxlink.h`) — це єдині «двері» для ручки,
   команди й порту; значення по радіо — 0…31;
3. пункт меню в `ui_rx.h` (`MENU_NAME`, `MENU_ICON`, `PARAM_ITEM`, `menuValue`, `menuChange`), значок у
   `rxs::menuIcon`;
4. рядок у вікні «Налаштування» передавача (`txui.h`: `RXS_NAME`, `rxsText`, `rxsStep`);
5. переклад, сцена в імітаторі, перевірка `i<№>=…` і `n`.

**…екран приймача:** функція малювання в `rxscreens.h` (тільки малювання, жодного заліза — тоді вона збирається й
на комп'ютері), номер `SC_…` і вибір у `ui_rx.h`, сцена в `tools/simrx/sim.cpp`.

**…команду порту:** гілка в `command()` (`hearlink.ino`) і рядок у шапці файлу.

**…якість звуку:** рядок у `QDEF` (`proto.h`); пакет має бути ≤ 250 байтів і «вміщуватися» (`qFits`).

## Своя емблема, свої звуки, своя мова
- емблема: `tools/gen_logo.py` → `logo.h`, `logo_oled.h`;
- шрифти: `tools/make_fonts.py`;
- звуки: `assets-src/` → `tools/make_sounds.py` → `tools/flash_assets.sh`;
- третя мова: зараз словник один (`lang_en.h`), вибір — `uiLang` 0/1; для третьої мови потрібен другий словник
  і розширення `tr()` у `lang.h`.
